# 入库任务的租约与并发安全

关联任务：#95、#97。

## 执行与提交边界

每次领取生成唯一的 `leaseOwner`。领取任务时，在短事务中使用 `FOR UPDATE SKIP LOCKED` 选择一条待处理或过期任务并更新租约；事务结束后才开始解析或调用向量模型。

| 步骤 | 是否持有任务行锁 | 写入内容 |
| --- | --- | --- |
| 领取任务 | 是 | RUNNING、负责人、截止时间、领取次数 |
| 开始处理 | 是 | 资料 PROCESSING |
| 原始内容解析 | 否 | 无数据库写入 |
| 提交解析结果 | 是 | 正文、内容哈希、INDEXING 阶段，在同一事务提交 |
| 切分与向量计算 | 否 | 仅构建内存中的 PreparedIndex |
| 提交索引结果 | 是 | 替换向量、资料 READY、任务 COMPLETED，在同一事务提交 |
| 失败处理 | 是 | 资料 FAILED、任务 FAILED、失败原因，在同一事务提交 |

`IngestionCommitter` 是 Worker 写入结果的唯一入口。它先获取任务行锁，检查 RUNNING、负责人和租约未过期，再进行提交。锁持续到整个提交事务结束，因此不会出现“检查通过之后，任务被接手，旧结果仍被写入”的窗口。

租约过期但尚未被别人领取时，旧负责人也没有提交或续租的资格。任务仓库的受保护读取/保存、向量替换要求调用者已有事务（MANDATORY），防止误用时提前释放锁或单独提交索引。

向量计算按有限分块数分批执行，提交只使用已计算好的向量，不调用模型。向量数据、JPA 资料和任务使用同一个数据源和 JpaTransactionManager；提交失败时，删除旧向量、插入新向量及状态变化一起回滚。分块 ID 由 documentId 和 chunkIndex 稳定生成，替换式写入支持恢复重做。

## 心跳与失效 Worker

独立调度线程执行心跳，避免被耗时解析或模型调用占满的工作线程池阻塞。续租成功只延长有效期，不增加领取次数、不修改处理阶段。

续租返回失败，或数据库异常导致结果不确定时，本地 Lease 标记失效。Worker 在解析/向量计算返回后丢弃结果；即使本地尚未观察到失效，最终数据库事务仍会拒绝过期、被接手或取消的负责人。

这不意味着能立即中止一个已发出的 HTTP 请求。它保护的是后续数据库写入，不保证外部模型只调用一次。心跳句柄在任务退出时关闭，完成、失败或失效任务不会持续续租。

## 删除、编辑与调度

删除、编辑、替换文件和失败重试，与 Worker 提交采用相同锁定顺序：先锁任务，再写资料/索引。编辑、替换和重试会清除旧负责人并重置任务；删除会取消任务，并在同一事务删除资料和索引。

若 Worker 先提交，随后删除会清理它刚写入的索引；若删除先提交，旧 Worker 无法提交迟到结果。文件存储抛出 IOException 时，替换事务也会回滚任务取消。

定时轮询只向有界工作线程池投递领取操作，不在调度线程执行文档处理。任务落库事务提交后才投递工作；线程池繁忙时保留数据库任务，由后续轮询消费。

## 配置与恢复前提

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| app.ingestion.lease-duration | 15m | 租约时长 |
| app.ingestion.heartbeat-interval | 30s | 心跳间隔，必须为正且短于租期 |
| app.ingestion.poll-interval | 1s | 轮询投递间隔 |
| app.ingestion.worker.core-pool-size | 2 | 核心工作线程数 |
| app.ingestion.worker.max-pool-size | 4 | 最大工作线程数，不含独立心跳线程 |
| app.ingestion.worker.queue-capacity | 20 | 内存中的工作唤醒队列容量 |
| app.ingestion.embedding-batch-size | 32 | 每次向量请求的最大分块数 |

恢复依赖 PostgreSQL 和原文件持久化存储仍可用。重新启动不会立即抢走尚未过期的租约，需要等待剩余租期。EXTRACTING 阶段可能重新解析；INDEXING 阶段复用已保存正文并重新计算向量。

当前租约采用应用的 LocalDateTime；多实例运行时必须统一时区并同步系统时钟。本次没有引入数据库迁移工具、数据库损坏修复或文件垃圾回收。

## 验证方法

`mvn test` 运行单元测试；`mvn verify` 额外通过 Failsafe 运行 `IngestionSafetyIT`，要求 Docker 可用。测试自行创建并清理 pgvector/pgvector:pg16 容器，不加载业务 .env 或真实 API Key。

集成测试使用生产任务仓库、Worker、提交器和向量存储；仅外部模型使用确定性向量替身，以验证事务和恢复逻辑而非模型质量。

- 并发领取同一任务只有一次成功，已锁任务会被跳过。
- 心跳使任务持续有效；过期和被接手的旧负责人无法提交结果。
- 错误维度触发真实 PostgreSQL 写入失败，验证原索引和两类状态都回滚。
- 删除先于迟到结果，以及删除等待正在提交的事务，两种顺序都不会残留索引。
- 编辑失效旧任务，文件替换失败回滚取消操作。
- 重复处理后只有一组分块，生产混合检索可读取新写入向量及元数据。
- 子进程提交 INDEXING 检查点后在模型调用处阻塞；强制结束该 JVM，不执行正常关闭逻辑；新 JVM 在租约过期后恢复并完成，领取次数增加且无重复索引。

该故障测试覆盖应用进程异常退出，不代表对数据库本身断电、磁盘损坏或文件丢失的验证。
